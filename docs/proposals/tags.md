# Предложение: проверка тегов и обложек (`soundsave tags`)

Статус: **реализовано** (`soundsave tags`).

## 1. Проблема

В фонотеке есть файлы, у которых не заполнены отдельные теги, отсутствует
обложка или нет текста песни. Часть файлов скачана старыми версиями
органайзера, часть — текущим `soundsave sync`; соглашения о тегах в архиве
различаются.

Нужна команда, которая:

1. проходит по существующему архиву;
2. сверяет теги, обложку и лирику с Yandex Music;
3. показывает расхождения;
4. с `--apply` вшивает **только отсутствующие** значения в существующие
   MP3/FLAC.

Аудио не скачивается и не заменяется, имена файлов не меняются. Команда не
вызывает `get_download_info`, `download` или `download_best_stream`.

## 2. Что показала разведка

Read-only прогон по текущей фонотеке (1648 файлов, все MP3):

| Показатель | Значение |
|---|---|
| Файлов | 1648 |
| Треков в текущем плейлисте | 1299 |
| Локальных файлов матчится по нормализованному `artist\|title` | 1195 (1180 точно + 15 fuzzy ≥ 0.90) |
| Не найдено в плейлисте — нужен поиск по каталогу | 453 |
| Без обложки | 362 |
| Без жанра | 737 |
| Без альбома | 338 |
| Без даты | 342 |
| Без album artist | 368 |
| Без лирики (`USLT` есть у 878) | 770 |
| Даты: полный timestamp / `YYYY` / `YYYY-MM-DD` | 380 / 925 / 1 |
| `TRCK` = локальный ID (старые `ID/1256`, новые `ID`) | 1648 |
| Title / artist расходятся с именем файла | 37 / 46 |
| `WOAF` с валидным URL | 0 (378 кадров есть, но URL пустой) |

Выводы:

* Точного Yandex ID в тегах сейчас нет. Матчинг строится в два шага: сначала
  по плейлисту, затем поиском по каталогу для оставшихся файлов.
* `WOAF` надо не только читать, но и заполнять: если кадра нет или URL пустой,
  записывается `https://music.yandex.ru/album/{album_id}/track/{track_id}`.
  Это одновременно исправляет тег и служит кэшем точного ID для следующих
  прогонов.
* `TRCK` в архиве — локальный ID, а не номер трека в альбоме. Это осознанное
  соглашение архива, поэтому поле не проверяется и не изменяется.

## 3. Границы первой итерации

* Источник — только Yandex Music (`YANDEX_TOKEN`). `PLAYLIST_URL` используется,
  если задан; без него команда работает в режиме поиска по каталогу.
* Только метаданные, обложка и лирика. Аудио не скачивается, не перекодируется
  и не заменяется.
* Файлы не переименовываются.
* `--apply` заполняет **только пустые** поля. Существующие значения не
  перезаписываются.
* `TRCK` и `TPOS` не читаются из Yandex, не проверяются и не изменяются: номер
  трека — строго локальный ID архива и может быть любым.
* `lyrics` заполняется, если поле пустое и Yandex отдаёт текст. Существующая
  лирика не перезаписывается.
* Comment, ReplayGain, cue-листы и прочие кадры не трогаются.
* Флага `--overwrite` в первой итерации нет. Конфликты показываются в отчёте,
  но не записываются.
* Обложка добавляется только если её нет (именно front cover). Существующая
  обложка не трогается.
* `WOAF` заполняется, если кадра нет или URL пустой.
* `WOAF`, обложка и лирика пишутся только при уверенном матче
  (`matched_woaf`/`matched_playlist`/`matched_search`), но не при
  `ambiguous`/`no_match`.

## 4. Источник данных

Используется существующий клиент `yandex_music.Client` и `YANDEX_TOKEN`.
Новых ключей не требуется. Если токен не задан — `ConfigError`.

Порядок получения данных:

1. Если задан `PLAYLIST_URL`, выполняется один запрос `users_playlists`.
   Если плейлист получить не удалось, пишется warning и команда продолжает
   работу в режиме поиска по каталогу.
2. Полные треки плейлиста загружаются пачками по 100 через `client.tracks`.
   Идентификаторы нормализуются к `str`: у `TrackShort.id` тип `int`, у
   `Track.id` — `str`.
3. Для файлов, которых нет в плейлисте, выполняется
   `client.search(f'{artist} {title}', type_='track')`; альбом в запрос не
   добавляется, потому что он заметно ухудшает выдачу Yandex, и используется
   только при ранжировании. Результаты ранжируются существующим
   `rank_candidates`. Если у результата поиска нет полного альбома, трек
   дозагружается через `client.tracks([id])`.
4. Обложка скачивается через `track.download_cover_bytes(size='orig')`.
5. Если локальная лирика пуста и `track.lyrics_info.has_available_text_lyrics`,
   текст запрашивается через `track.get_lyrics(format_='TEXT')`. Запрос
   выполняется только при `--apply`; для отчёта достаточно признака
   `lyrics_available`. Ответ `NotFoundError` считается отсутствием текста, а не
   ошибкой.

Ошибки сети, пустые результаты поиска и ошибки лирики/обложки не прерывают
прогон: файл попадает в отчёт со статусом `no_match`/`error`, а ошибка
лирики или обложки фиксируется в соответствующем поле. Остальные поля при
этом записываются.

## 5. Матчинг

Приоритет источников для каждого локального файла:

1. **Точный `WOAF`.** Если в теге есть валидный
   `https://music.yandex.ru/album/{album_id}/track/{track_id}`, трек берётся по
   ID без поиска. Это основной путь после первого успешного `--apply`.
   ID проверяется по artist/title/duration; при расхождении, ошибке или
   недоступности трека выполняется fallback, а `url` попадает в `conflicts`.
2. **Точный ключ плейлиста.** Нормализованный `artist|title` (через
   `matching.normalize`) ищется в индексе плейлиста. При нескольких кандидатах
   выбирается ближайший по длительности; если длительности нет — `ambiguous`.
3. **Fuzzy по плейлисту.** Если точного ключа нет, сравниваются artist/title с
   порогом ≥ 0.90 и длительность в допуске.
4. **Поиск по каталогу.** `client.search` + `rank_candidates` с
   `min_score`/`duration_tolerance` из конфигурации. Живые версии, каверы,
   ремиксы и т. п. отсекаются существующими фильтрами `matching.py`.

Для 37/46 файлов, где теги расходятся с именем файла, запрос строится в двух
вариантах: по тегам и по имени файла. Это повышает шанс найти трек, не меняя
при этом ни теги, ни имя.

Между сетевыми запросами (поиск и лирика) выдерживается `config.delay`
(по умолчанию 1 с). При 453 файлах без плейлиста это примерно 8 минут только
на поиск; лирика добавляет запросы для файлов, где поле пусто и Yandex отдаёт
текст.

## 6. Какие поля заполняются

| Поле | Источник | Правило |
|---|---|---|
| `title` | `full_title(track)` | только если пусто |
| `artists` | `track.artists` | только если пусто |
| `album` | `full_title(album)` | только если пусто |
| `album_artist` | `album.artists` | только если пусто |
| `date` | `album.release_date` → `YYYY-MM-DD`, иначе `album.year` → `YYYY` | только если пусто |
| `genre` | `album.genre` | только если пусто |
| `cover` | `track.download_cover_bytes(size='orig')` | только если обложки нет |
| `WOAF` | ссылка на трек | если кадра нет или URL пустой |
| `lyrics` | `track.get_lyrics(format_='TEXT')` | только если пусто и текст доступен |
| `TRCK`, `TPOS` | — | никогда |
| `comment` | — | никогда |

`album.genre` у Yandex находится на уровне альбома; у трека отдельного жанра
нет. Если жанр альбома пуст, поле остаётся пустым.

`WOAF` пишется только если известны `album.id` и `track.id`; иначе кадр не
добавляется.

Лирика запрашивается только при `--apply`; в отчёте показывается
`lyrics_available`, без скачивания текста.

## 7. Запись тегов

Нужен новый публичный `archive.update_tag_data(path, data, *, cover_mode='missing')`.
В первой итерации поддерживается только `cover_mode='missing'`.
Существующие `_write_mp3_tags` и `_write_flac_tags` заменяют весь блок тегов и
для обогащения не годятся: они потеряют TXXX, PRIV, cue-листы, ReplayGain и
другие кадры.

Правила:

* **MP3.** Загрузить существующий `ID3` (или создать при `ID3NoHeaderError`),
  обновить только целевые кадры, остальные сохранить. Обложка — `APIC` type 3
  (front cover); добавляется только при отсутствии. Наличие back cover или
  другой картинки обложкой не считается.
* **FLAC.** Загрузить `FLAC`, обновить только целевые Vorbis comments.
  Обложка — front cover (`Picture.type == 3`); добавляется только при
  отсутствии, остальные pictures сохраняются.
* **Лирика.** MP3 — `USLT` (как в `sync.set_tags`), FLAC — `lyrics`.
  Добавляется только если `TagData.lyrics` пуст; существующий текст не
  перезаписывается. Наличие проверяется по любому непустому `USLT`/`lyrics`,
  а не только по первому кадру.
* **Атомарность.** Файл копируется в `TARGET_DIR/.soundsave/tmp/`, теги
  записываются в копию, результат проверяется через `mutagen`, затем
  выполняется `os.replace`. При ошибке оригинал остаётся нетронутым, временный
  файл удаляется.
* **Проверка после записи.** Повторно прочитать `TagData` и убедиться, что
  целевые поля записались, а аудио открывается `mutagen.File`.
* **Права и mtime.** `shutil.copy2` сохраняет метаданные файла; после записи
  тегов mtime меняется ожидаемо.

Текущий `read_tag_data()` возвращает первый `APIC`/`picture` независимо от
типа. Для этой команды нужен признак именно front cover: добавить `cover_type`
в `TagData` или helper `has_front_cover(path)`.

`get_image_type()` выносится в `archive.py`, `full_title()` — в
`yandex_catalog.py`. `sync.py` импортирует их оттуда, чтобы `tags` не тянул
Yandex-специфичный `sync` и не создавал циклических импортов.

## 8. CLI

```bash
soundsave tags                          # отчёт, файлы не меняются
soundsave tags --apply                  # вшить только отсутствующее
soundsave tags --apply --no-lyrics      # без лирики, только теги и обложка
soundsave tags --no-search              # только плейлист, без поиска
soundsave tags --id 42 --limit 100 --csv tags.csv --json tags.json
soundsave tags --playlist Chill         # проверить другой плейлист
soundsave tags --playlist Chill --apply # заполнить пропуски в другом плейлисте
```

Аргументы:

* `--dir`, `--limit`, `--id` — общие аргументы сканирования архива.
* `--playlist NAME` — проверить папку-плейлист `NAME` (непосредственную
  подпапку `MUSIC_DIR`) вместо `TARGET_DIR`. Без отдельного `MUSIC_DIR` папка
  ищется рядом с `TARGET_DIR`. Несовместим с `--dir`. `--apply` пишет в
  выбранную папку, а временные файлы создаются в её `.soundsave/tmp/`.
* `--min-score`, `--duration-tolerance` — пороги для поиска по каталогу.
* `--delay` — пауза между поисковыми запросами.
* `--csv`, `--json` — отчёты.
* `--apply` — включить запись.
* `--no-search` — не обращаться к поиску по каталогу; файлы вне плейлиста
  остаются в отчёте как `no_match`.
* `--no-lyrics` — не запрашивать и не записывать лирику.

Команда возвращает `0`, если прогон завершился, даже при наличии `no_match`.
Код `1` — только при фатальных ошибках конфигурации/архива.

## 9. Отчёт

`MetadataReportRow`:

* `path`, `file_id`, `artist`, `title`, `album`, `duration_s`;
* `status`: `matched_woaf`, `matched_playlist`, `matched_search`,
  `ambiguous`, `no_match`, `error`;
* `source_id`, `source_url`, `confidence`;
* `missing` — список пустых полей, которые можно заполнить;
* `conflicts` — список полей, где значения расходятся (только для информации,
  не записываются);
* `cover`: `unknown`, `present`, `missing`, `added`, `unavailable`, `error`;
* `lyrics`: `unknown`, `present`, `missing`, `added`, `unavailable`, `skipped`, `error`;
* `applied` — были ли изменения;
* `error`.

`unknown` у обложки/лирики означает, что уверенного матча не было и поле не
проверялось.

`report.write_csv`/`write_json` обобщаются параметром типа строки, чтобы не
дублировать код для `ReportRow` и `MetadataReportRow`.

Сводка в консоль: количество по статусам, сколько полей заполнено, сколько
обложек и текстов добавлено, сколько конфликтов и ошибок.

## 11. Тестирование

Ключевые случаи:

* плейлист: точный ключ, fuzzy, дубликат с разной длительностью, отсутствие
  совпадения;
* поиск: `MATCHED`, `AMBIGUOUS`, `NO_MATCH`, пустой `tracks.results`;
* `--apply` не меняет непустые поля;
* `--apply` не меняет `TRCK`/`TPOS` даже если Yandex вернул номер трека;
* существующая обложка не заменяется;
* пустая лирика заполняется, существующая — не перезаписывается;
* `lyrics_info` без текста и `--no-lyrics` не приводят к запросу;
* ошибка `get_lyrics` не мешает записать остальные поля;
* пустой `WOAF` заполняется, валидный — используется для точного матчинга;
* неизвестные ID3-кадры (TXXX/PRIV) и FLAC pictures сохраняются;
* атомарная запись: при ошибке оригинал не меняется, временный файл удалён;
* CSV/JSON содержат `MetadataReportRow`;
* CLI: `tags` без `--apply` ничего не пишет, с `--apply` пишет.

Все тесты — без сети, с fake-клиентом и fake MP3-файлами, как в существующем
наборе.

## 12. Ограничения и что дальше

В первую итерацию не входят:

* исправление конфликтов (`--overwrite`);
* реальные номера треков (`TRCK`/`TPOS`);
* другие источники (MusicBrainz, AcoustID, Deezer, iTunes);
* SQLite-кэш результатов поиска (его роль выполняет `WOAF`).

Следующие итерации могут добавить `--overwrite`, AcoustID для файлов с
испорченными тегами и MusicBrainz/Cover Art Archive как ещё один источник.

## 13. Discogs fallback (итерация 2)

Discogs добавлен как дополнительный источник метаданных и обложек.

* `DISCOGS_TOKEN` — personal access token; без него Discogs отключается.
* `DISCOGS_DELAY=2.0` — минимум 2 секунды между запросами (30/мин при лимите
  60/мин для авторизованных). На `429` используется `Retry-After`, до трёх
  попыток.
* `--source both` — поведение по умолчанию: Yandex первым, Discogs только если
  Yandex вернул `no_match`/`ambiguous`/`error`.
* `--source yandex` — только Yandex.
* `--source discogs` — только Discogs; Yandex-плейлист не загружается. Удобно
  после уже выполненного Yandex-прохода. Файлы, у которых нет полей, которые
  Discogs может заполнить, по умолчанию пропускаются; `--no-skip-complete`
  заставляет запрашивать Discogs для каждого файла.
* `--no-search` отключает поиск у выбранных источников; с `--source discogs`
  комбинация запрещена.
* `--discogs-delay` переопределяет `DISCOGS_DELAY`.

Матчинг Discogs:

1. `GET /database/search` с `artist` + `track`, `type=release`, `per_page=5`.
2. Дедупликация результатов по `title`/`year`, затем до трёх
   `GET /releases/{id}`.
3. Поиск трека в `tracklist` по названию и длительности через `matching.py`;
   заголовки и индексы пропускаются.
4. Заполняются `album`, `album_artist`, `date`, `genre` (сначала `styles[0]`,
   затем `genres[0]`) и front cover (primary image).
5. `lyrics` не заполняется: Discogs не отдаёт тексты.
6. `WOAF` не заполняется: он остаётся точным кэшем Yandex-трека.

`CompositeCatalog` вызывает Yandex первым и передаёт управление Discogs только
при неуверенном результате. `MetadataReportRow` получает поле `source`
(`yandex`/`discogs`), статус — `matched_discogs`.

Скорость: один файл — один поиск и до трёх запросов релиза, примерно 8 секунд
при `DISCOGS_DELAY=2`. Полный прогон по 444 файлам вне плейлиста занимает около
часа; `--limit` позволяет обрабатывать частями.
